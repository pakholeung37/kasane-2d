# CDI3 wire boundary (P1-A)

`kasane-live2d::cdi3` owns only the display-information JSON boundary. Its IDs
are external Live2D runtime IDs, not document UUIDs or display names. The
module performs no file I/O and does not resolve a CDI against a MOC, model,
Document, or SDK asset. The API is `decode_cdi3(&str)`, `validate_cdi3(&Cdi3)`,
and `encode_cdi3(&Cdi3)`; errors and diagnostics carry JSONPath-like `path`
values for the later project adapter.

The typed fields are `Version: 3`, optional `Parameters` with `Id`, `GroupId`,
`Name`; optional `ParameterGroups` with the same fields; optional `Parts` with
`Id`, `Name`; and optional `CombinedParameters` as arrays of runtime IDs.
Collection order is preserved. A missing collection and an empty array stay
distinct. An explicit JSON `null` for a known optional collection decodes as
absent and is omitted when re-encoded, matching the Framework getter's
absence behavior. Unknown root and item fields are kept as JSON values, and
duplicate JSON member names are rejected before serde can overwrite one.
Programmatically inserted extension keys that collide with a typed field
block writing.

Diagnostics are separated by scope:

| Domain | Findings | Meaning |
| --- | --- | --- |
| `FileStructure` | wrong Version, empty or duplicate IDs, missing parent group, group-parent cycle, empty combination, repeated member, extension key collision | The CDI is internally inconsistent and cannot be written. |
| `ModelDependency` | combination member not listed in CDI | Warning only: the runtime ID might exist in the model; writing remains allowed. CDI is not required to list every model parameter. |
| `FrameworkEncoding` | unsupported control character or `UnsupportedExtensionNumber` | The **P1-A writer** has not verified a safe representation for that value in the pinned Framework parser. Decode retains it, while encode refuses it with a field path. This does not assert that all numbers are unsupported by Framework. |

The serializer writes raw UTF-8 names, including Chinese text, and standard
escapes for quotation marks, backslashes, and supported controls. The pinned
Framework `CubismJson::ParseString` handles `\b`, `\f`, `\n`, `\r`, and `\t`
but rejects `\u` escapes. Thus the writer diagnoses remaining U+0000–U+001F
characters, whose JSON encoding would require `\u`; for example U+0001 is
rejected. The CPU probe verified a generated CDI with raw Chinese, quotes,
backslashes, newline, tab, unknown text and boolean fields, and a combination.
A separate standard-valid JSON control containing `\u0001` was rejected by
the official parser. This is a focused parser check, not a guarantee about
unverified extensions or rendering.

The self-made fixture is generated by
`modules/kasane-live2d/examples/cdi_fixture.rs`. To rebuild and read it using
the local, unmodified Native SDK Framework/Core:

```sh
cargo fmt -p kasane-live2d --check
cargo clippy -p kasane-live2d --all-targets -- -D warnings
cargo test -p kasane-live2d
uv run --locked python tools/run_framework_cdi_probe.py
```

The last command writes `target/cdi-probe-results/report.json`, the emitted
`fixture.cdi3.json`, the official getter output, and command logs. The runner
sets the report to `status=failed, phase=incomplete` before running so an
interrupted repeat cannot leave an old pass. It rebuilds the dedicated CPU
target and records hashes of the Framework sources, Core library, probe,
writer, fixture source, runner, and generated CDI. The CPU targets alone link
the local `CubismRenderer::StaticRelease()` no-op used during normal Framework
dispose; no renderer or GPU resources are created. The GPU probe and
production code do not link this shim.

`CubismCdiJson` exposes getters for the four collections but no Version or
unknown-field getters. The CPU probe checks those two categories through the
same official `CubismJson` parser and reports them separately. This boundary
does not verify CDI use by an editor, model-ID resolution, image output, or
future Framework releases.
