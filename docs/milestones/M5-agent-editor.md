# M5：Godot Agent-first editor

状态：应用壳已建立，功能待实施、未验收（见 [应用说明](../../apps/editor/)）。依赖：M1–M4。返回 [总路线图](../ROADMAP.md)。

## 1. 交付结果

正式 Godot 应用能够新建工程、导入 PNG 或 MOC3，由 Agent 使用 GDScript 编辑完整模型，检查参数状态，保存重开，导出并在现有运行时验证。

正式入口置于 `apps/editor/`，交付可直接启动的桌面应用及可复现的构建、导出说明。用户不需要安装 Godot、创建 Godot 项目或安装 addon。

应用构建负责将 `kasane-godot` 原生库、GDExtension 加载配置、Rust renderer 资源与应用脚本打包。开发环境的模块产物位于 `target/release/`；不向用户分发此目录作为产品，不提供通用 addon 安装流程。正式代码不引用 `demos/` 的脚本或 fixture。

本里程碑交付 Godot 项目、应用导出配置、构建打包入口及目标平台的应用产物。开发启动和打包应用使用同一份代码；验收必须启动打包产物，不能仅在 Godot 编辑器里运行场景。

## 2. GDScript 编辑能力

Godot 数据绑定对象持有 Document，不继承 Node2D。对象句柄以拥有者、文档代次和稳定 ID 校验寿命；打开另一工程或删除对象后旧句柄明确失效。

| 对象/功能 | 必须能通过 GDScript 完成 |
|---|---|
| 工程 | 新建、保存、另存为、打开、MOC3 导入/导出、资源诊断 |
| 素材 | PNG 导入、尺寸读取、纹理引用、显式替换与重新定位 |
| Part | 创建、遍历、重命名、组织关系修改、合法删除 |
| Mesh | 创建、读取/批量更新位置、UV、拓扑；增删、纹理与绘制属性修改 |
| Deformer | 创建 Rotation/Warp、读取/修改、设置/解除变形父节点、删除 |
| Parameter | 创建、范围/默认值修改、查询引用、合法删除 |
| Binding / Keyform | 创建/修改/解除绑定；按明确关键值组合读取、写入和补齐完整形态集合 |
| 预览 | 设置临时参数、求值、读取最终 drawable 数据、全图/对象裁剪截图 |

接口说明必须覆盖类型、属性、可写性、方法返回值、数组复制/写回规则和约束。Agent 不依赖 fixture UUID 或猜测方法名。Godot 类型反射加完整接口说明即可，不先建立通用 RNA 系统。

全部数据访问在主线程进行，Packed 数组读取为副本，批量更新显式写回。提供返回结构化错误的操作入口；不能只通过属性 setter 的日志表达失败。

直接脚本不自动建立事务或撤销步骤；运行错误前完成的写入保留，并报告起止 revision。可选 Action 复用 Godot UndoRedo，明确整文档快照恢复范围，不承诺回滚文件和其他外部副作用。

## 3. PNG 建模入口

- 接受全画布透明 PNG，或 PNG 加显式原画尺寸、裁剪偏移。
- 将图层位置转换到 M1 定义的源坐标，保留纹理方向和画布关系。
- 提供生成初始矩形网格的普通数据操作；Agent 可再通过几何 API 修改。自动三角剖分不在本轮范围。
- 文件名可以成为初始显示名，稳定 ID 由应用生成；更换素材不要求修改应用源码。
- 源位置只有一份权威表达，不同时维护相互冲突的节点 transform 和可编辑顶点偏移。

## 4. 最小应用界面

| 界面 | 必须完成的操作 |
|---|---|
| 工程栏 | 新建、打开、保存、另存为、导入/导出；显示当前路径与未保存状态 |
| 画布 | 缩放、平移、适配全部内容、定位选中对象、高亮，使用 M4 renderer |
| 对象树 | 显示 Part/mesh/deformer 与组织关系；显示和跳转变形父关系，不混为一个树 |
| 属性检查 | 对象 ID、类型、素材、基础属性、绑定、指定 Keyform、资源/校验错误 |
| 参数预览 | 按参数范围调整临时值、恢复默认、显示当前采样值 |
| 脚本结果 | 执行状态、日志、结构化结果、错误位置、起止文档版本、观察产物 |

UI 修改调用同一数据接口。选择、相机、预览值和 UndoRedo 属于应用临时状态，不写进模型字段；不要求额外 Session 框架。

## 5. Agent 自动执行与观察

提供一个文档化的本地脚本文件执行入口，能操作已运行应用中的当前工程，无需人逐次点击 Run。首版采用本地请求/结果目录：完整脚本和元数据写临时文件后原子发布，应用串行消费并写结果。它只传整段脚本，不提供逐顶点远程调用。

请求包含唯一执行 ID、目标文档代次和脚本路径；重复 ID 不重复执行，旧代次请求拒绝。结果包含编译/运行/业务结果、起止 revision、日志与截图元数据；未执行与执行后失败分别表达。打开工程时清除旧目标的待执行请求，不能把它们自动改指新文档。

围绕新的 Document 绑定实现脚本宿主，提供编译和运行错误的行号与消息收集。错误捕获必须通过实际 Godot 版本测试；无结果标记不能替代具体错误证据。同步短脚本不承诺强制取消或沙箱，阻塞时不得输出虚假的“已取消”。

观察使用 M4 的版本就绪状态，包含文档代次/revision、实际预览参数、相机和图像尺寸。图片缺失、求值失败或上传失败时明确失败；不能输出旧画面作为当前结果。

## 6. 实施顺序

1. 从 Bridge 提取数据绑定，按新接口实现应用内脚本执行和可选 Action；不丢失句柄寿命检查。
2. 暴露完整 M1 数据能力，建立逐对象脚本测试；接入 M2/M3 文件操作。
3. 建立应用入口与 PNG 导入，接入公共 renderer 和最小检查界面。
4. 接入自动执行与观察，完成下面两条端到端流程。

## 7. 验收

遵守 [统一验收规则](../VALIDATION.md)，必须在正式应用中完成：

| 流程 | 必须执行的步骤 |
|---|---|
| 从素材制作 | 导入至少两组不同尺寸/位置的 PNG 素材，各自创建 mesh、Part、Rotation/Warp、参数与 Keyform；观察关键值和中点，保存重开、导出、运行 |
| 从 MOC3 编辑 | 导入 M3 的外部模型，通过 GDScript 修改几何形态、变形关系、参数绑定和绘制属性；保存重开、再导出、运行 |
| 持续修改 | 第二段脚本读取第一段脚本产生的对象 ID 后修改，不能每次删除重建模型 |
| 接口完整性 | 上表每种对象的创建/读取/修改/删除与失败路径均有脚本记录；不能依赖未公开 C++ 辅助入口 |
| Agent 自检 | Agent 读取数据与观察图，指出一个具体问题并修改，保留修改前后证据；不以固定演示脚本冒充此记录 |
| 错误恢复 | 编译错误不修改 Document；运行错误报告已完成写入；显式 Action 按范围恢复；旧句柄/旧请求不修改新工程 |
| 应用交付 | 从独立目录启动打包应用，在无 Godot 开发环境和仓库路径的环境完成打开、编辑、保存和导出；内部原生库及资源随包加载 |
| UI / 脚本一致 | UI 参数预览不改 Keyform；脚本修改即时出现在检查面板，保存结果一致 |

导出包在不运行 editor 的现有运行时中加载。最终数据和画面对照通过，才能认定编辑器闭环完成；界面搭建或脚本按钮可用不构成完成。
