# M6：独立 Godot MOC3 viewer

状态：应用壳已建立，功能待实施、未验收（见 [应用说明](../../apps/viewer/)）。依赖：现有运行时、M4；安排在 M5 后。返回 [总路线图](../ROADMAP.md)。

## 1. 交付结果

提供正式 Godot 浏览应用，用户选择模型后直接查看与调整参数，无需修改 demo 常量、导入编辑工程或启动 editor。入口置于 `apps/viewer/`。

## 2. 输入与功能

- 打开 `model3.json` 及其引用的 MOC3/纹理。
- 直接打开 `.moc3` 时要求明确的纹理槽映射，不猜测图片路径。
- 经 PurismCore C99 FFI 加载、驱动 MOC3，将运行帧转换为 M4 的绘制契约，使用 `kasane-godot` Rust renderer；`gd-cubism` 保持独立，用于画面对照。
- 显示模型路径、文件版本、画布、参数 ID/范围/默认值；调整参数、恢复默认。
- 缩放、平移、适配画布、设置背景、保存当前状态截图。
- 缺文件、未知版本、无效模型和纹理错误显示具体原因，失败不覆盖当前有效模型。

viewer 不加载 Document、工程编解码、UndoRedo 或编辑脚本宿主，不提供建模操作。不重新实现参数插值和变形；现有运行时支持范围与编辑器导入范围分别显示。

## 3. 实施步骤

1. 将 PurismCore 的运行模型装载/参数驱动经 C99 FFI 接入可选择路径的正式入口。
2. 增加参数列表、画布操作和错误反馈，使用公共 renderer。
3. 将模型更换作为独立生命周期操作，释放旧模型和绘制资源。
4. 提供构建、启动说明和不依赖 editor 的分发产物。

## 4. 验收

遵守 [统一验收规则](../VALIDATION.md)。

| 用例 | 必须验证 |
|---|---|
| 现有模型 | 原 demo 使用的模型可从文件选择打开，相同参数画面与原路径一致 |
| 编辑器产物 | M5 两条流程的导出包均可打开，关键值与中点图像通过对照 |
| 裸 MOC3 | 提供多纹理槽映射可显示；缺映射明确报错 |
| 连续更换 | 至少连续切换两种模型十次，无旧图残留、悬空节点或持续资源增长 |
| 失败处理 | 坏文件、缺纹理、运行时不支持的版本不崩溃，保留当前模型 |
| 独立运行 | 仅分发 viewer、运行依赖和模型即可启动，不读取 editor 目录或工程文件 |

M1–M5 使用现有运行时做验证，不以本 viewer 尚未完成为阻塞理由。
