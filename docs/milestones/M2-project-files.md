# M2：Document 工程持久化

状态：待实施，未验收。依赖：M1 数据契约；可随 M1 实施。返回 [总路线图](../ROADMAP.md)。

## 1. 交付结果

把完整 Document 保存为可搬移的工程，关闭进程后重开，继续编辑并导出等价运行模型。保存工程不要求生成 MOC3，也不要求有 Godot 画布或 GPU。

## 2. 文件契约

采用目录工程：一个版本化 JSON 工程文件和 `assets/` 素材目录。工程文件记录格式标识、格式版本和全部持久化对象，素材使用相对工程根目录的路径。

| 保存内容 | 要求 |
|---|---|
| Document | M1 的所有源字段，包括稳定 ID、运行时 ID、名称、画布、对象顺序 |
| 引用 | 素材、Part、变形父子、遮罩、参数绑定；以稳定 ID 保存 |
| 几何和形态 | 基础几何、顶点 ID、UV、拓扑、全部 Keyform 和绑定轴顺序 |
| 图片 | 相对路径、尺寸、内容 SHA-256；导入的图片复制到工程内部 |
| 版本 | 新格式不沿用旧 v1/v2 的版本含义；未来未知版本明确拒绝 |

不保存 GPU RID、内存地址、求值缓存、运行时稠密索引、选择、相机、临时预览参数、脚本实例和 UndoRedo 栈。编辑状态不参与模型内容是否已保存的判断。

字段的类型、必需性、默认值、引用约束、数值精度写入随实现交付的格式说明。序列化精度应保证所采用源数值类型的往返，不能为缩小文件截断坐标。

## 3. 保存与打开

1. 图片复制使用独立名称，禁止覆盖已被旧工程引用的文件；先成功落盘素材，再写工程清单。
2. 工程清单在同目录写临时文件，检查写入结果后原子替换。失败保持原清单和原素材可读；未引用素材不在保存过程中自动删除。
3. “另存为”复制所有引用素材并重写相对路径；不能遗留旧工程绝对路径或 `res://` 依赖。
4. 打开先解析候选 Document、验证结构和引用，再替换当前文档。格式/结构错误不留下半份新文档。
5. 图片缺失或哈希/尺寸不符时，允许打开源结构并列出资源诊断，但预览标记不完整，MOC3 资源包导出失败。重定位素材必须校验；确认内容变化应通过显式素材替换操作。
6. `modified` 比较持久化内容与最后一次成功保存状态；仅移动相机、预览参数不会变脏，撤销回同一源内容后恢复未修改。

旧实验工程采取明确拒绝策略，并返回旧格式版本与原因；本轮不承诺自动迁移简单 Warp。旧 Stage 样例已删除；为新格式建立构造输入，不以旧样例约束新数据模型。

## 4. 实施与模块

- 从 `document_bridge.cpp` 提取编解码、文件发布和资源路径解析；编解码可在无场景树时测试。
- 解码通过 Document 校验建立对象，不能靠直接填充私有字段绕过引用和 Keyform 约束。
- 外部 PNG 通过图片解码加载，不能要求 Godot 编辑器先生成 `.import` 文件。
- 数据快照用于撤销时以源数据为准；纹理缓存可共享，文件复制等外部副作用不作为撤销承诺。
- 为全部 M1 类型建立字段覆盖表，增加字段时同时更新保存、读取与等价检查。

## 5. 验收

遵守 [统一验收规则](../VALIDATION.md)。

| 用例 | 必须验证 |
|---|---|
| 完整模型保存重开 | M1 全部持久化字段一致，包括多参数 Keyform、遮罩、嵌套变形 |
| 搬移工程目录 | 移走原路径，清除 Godot 导入缓存后仍能打开、显示和导出 |
| 继续编辑 | 重开后改 Keyform、重绑定、增删对象，再保存、重开、导出 |
| 求值和导出 | 保存前后按相同参数采样比较；输出文件的运行语义一致 |
| 保存失败 | 只读目录/写失败/发布失败后原工程可打开，modified 未被误清除 |
| 打开失败 | 截断 JSON、未知版本、悬空引用、缺形态不替换当前文档 |
| 素材诊断 | 缺图片和尺寸/内容变化有对象级诊断，不能显示缓存旧图并声称资源完整 |
| 保存状态 | 预览不变脏；改源数据变脏；恢复已保存源内容后不变脏 |

交付格式说明、读写实现、可搬移样例和跨进程往返报告。仅把旧 Bridge 的 JSON 方法换目录不构成完成。
