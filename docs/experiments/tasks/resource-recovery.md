# S3-B：恢复失联纹理并交付

这是待生成任务包的公开任务模板。发放时主持人提供完整 input、公开 SDK 文档、
共享 Python 的绝对路径和 20 分钟运行预算；未提供这些材料时不启动。

`input/project/` 是一个既有 Kasane 工程。其中恰有一项纹理失联，其余结构完整。
原素材的一个正确副本在 `input/candidates/`，这个目录也有其他 PNG。请诊断问题、
辨认正确素材，在新的输出位置恢复工程，并导出可使用的 model3/MOC3/纹理包。

这是一项恢复任务：纹理内容、名称和对象身份应与工程原记录一致，不能用空白图或
“看起来差不多”的图片替代。所有几何、参数、关键形态、层级与其他对象保持不变。
输入目录和素材不得被覆盖；资源引用在恢复和保存时允许迁移。

请提交：

- `solution.py --output <绝对目录>` 和需要的辅助文件，可从同一输入重复创建结果。
- 输出根内的工程与导出包，以及 `result.json`：`project_manifest`、`package_model3`
  均为实际绝对路径，子目录和文件名可自选。
- `notes.md`：记录原问题、选择素材的依据、验证方法、失败尝试与依赖用途。

请确认工程能重开、资源诊断通过，且输出复制到新目录后能独立使用。
不要求提交 GPU 渲染图片。数值内容保持检查的绝对容差为 `1e-6`。

使用公开 kasane API 修改工程，不直接编辑工程 JSON/MOC3，不修改 input 或文档。
可以读取/比较候选 PNG，也可以在本轮共享环境安装依赖：
`uv pip install --python <本轮共享Python> <包名>`。不要求新环境或独立锁文件。
不得替换被测 SDK，也不要读取主持人的预期结果、其他受试目录或仓库实现。
