## 素材事实与验收边界

当前素材位于 `models/local/Shirousagi`。在 Git `cd04db1` 的 `observe` wheel 上，
主持人预检得到：

| 来源 | 公开 SDK 导入结果 |
| --- | --- |
| 交付的 model3/MOC3 与 2048×2048 纹理 | 4225×4000 画布；24 mesh、34 参数、17 变形器、15 mesh binding、17 scene binding；资源和结构诊断均为空。 |
| 由该模型转出的 PSD | **24 个 raster 图层**、24 mesh、24 PNG 资产；名称与模型的 24 个 ArtMesh 一一对应；其中 12 层在默认姿态可见，另 12 层保留为隐藏的表情素材。导入无 warning，资源和结构诊断均为空。 |

PSD 是默认姿态的分层美术快照，不包含原模型的参数关键形态、变形器与 rig。
它可以用于确定图层身份和原始画面，不能单独充当 34 参数动态行为的标准答案。
在 1024×1024 的相同 Observer 设置下，PSD 导入工程与 model3 默认姿态有
44,651 / 1,048,576 个像素不同；在分析差异来源前，跨来源比较不得设为零像素门槛。

交付模型的可迁移性则有精确基线：从当前 wheel 导入、保存、导出 package、复制到
新目录重导入，10 个覆盖角度、眨眼、嘴型和表情的姿态在 512×512 Observer 中
逐像素一致，且没有诊断或 warning。后续修复题应以该模型在同一 wheel 中的
观察结果作行为 oracle，不能以 PSD 导入工程的像素作动态 oracle。

本次预检的素材 SHA-256：PSD `d8c2e2184e2c87f56d3b777561a1386b86b82c784dd94a2bda85bbf649745fbf`；
MOC3 `62a460099334f4bccea63ec9a5ff7f84ba8be05e28ef5ce6f047713451ddce1b`；
model3 `c430f242983434c7de8b2c792d88457f0b57b5887e5460b2033c3b9c2165f477`；

## S6：真实 rig 的盲诊与局部修复（首关）

主持人从原模型生成可编辑工程，仅向受试者发放一份**被注入单一故障**的工程、
对应 PSD、故障描述、少量带参数值的正确参考帧以及公开 SDK 文档。不给原始
model3/MOC3、目标对象 ID、错误字段、位移量或完整真值工程。首版只扰动一个
受多个参数控制的非默认 scene keyform，使问题仅在特定组合姿态出现，默认姿态
基本正常。PSD 的同名图层和默认美术可帮助判断是素材还是 rig 出错。

给受试者的需求用症状表述，例如“转头并闭眼时一侧眼部轮廓错位；默认姿态和另一侧
眼睛应保持”。要求其说明定位依据，用公开 API 修改并保存工程，交付可搬迁 package、
自检脚本和观察报告。参考帧只覆盖部分姿态，不泄露评估使用的其他参数组合。

公共 API 的本地 pilot 已证明：对此类单 keyform 扰动，默认与无关姿态不变，
组合姿态产生明显局部像素差；逆向修复后六个试验姿态与原模型逐像素一致。
这只证明一种注入方式可解，不替代三个正式变体各自的控制检查。

**正式发放门槛：** 主持人须先用同一冻结 wheel 和公开 SDK 完成 oracle 修复并
通过正控制；不修改的工程、改错 keyform、整体移动父级、改纹理/PSD、只交 PNG
和仅对公开姿态拟合的脚本均须被负控制拒绝。三个试次使用同一种故障语义，改变
左右侧、角度角点和幅度；每个变体均独立预检，避免固定数字答案。

已执行的 S6 预检：三种变体的正确控制通过，不修改、修正量错误与改错关键形态
均失败；另在独立控制实验中，正确脚本的原作品和空目录重放通过。其余负控制
仍是正式判分必须覆盖的要求，不能把尚未实现的控制写成已验证。

**判分：** 原作品和空目录重放分别检查输入哈希、资源/结构诊断、工程重开、
package 搬迁、对象身份与非目标状态；在公开姿态和未公开的角度 × 眨眼组合上，
比较完整渲染帧及受影响 mesh 的求值几何。行为正确、非目标保持和可交付性分别
报告；定位过程及 API 障碍另作证据审阅。零像素要求只用于同源原模型的修复前后
参考，允许不同内部修法的受试作品须在 pilot 中验证判分不会错误拒绝。

## S7：从 24 层 PSD 创建可编辑的局部动态行为

仅在 S6 的作品与判分稳定后开放。受试者从 PSD 导入的静态工程出发，收到交付
模型的双眼表情姿态参考图，但不拿到可复制的 rig。
要求保留 24 层、隐藏素材、图层顺序与资产，创作两个独立眼部参数及其完整关键形态，
并在未公开中间值保持连续，另检查左右参数组合。先选**一个局部行为**，不要求重建
34 个参数；否则失败无法归因，也无法在合理预算内建立公开 API oracle。

这一关主要检验真实分层美术上的网格与绑定创作。PSD 工程的矩形 mesh 与原模型的
复杂拓扑不同，因此不能直接要求与交付模型逐像素一致。主持人先试了三层嘴部
形变，虽能保存和导出，画面明显不对；将首个可归因目标改为双眼独立眨眼。公开
SDK pilot 使眼部参考裁剪区的平均 RGB 误差相对静态 PSD 降至约 11%（左参数）
和 23%（右参数），同时保持眼外画面不变。判分限定眼部区域改善、双眼组合与
中间值，默认和眼外画面必须与 PSD 工程逐像素一致；正控制及不修改、只做单眼、
运行时 ID 错误、无效形变的负控制都通过预期门槛。

pilot 同时揭示两个系统缺口：新建参数无法指定导出 MOC3 的 runtime ID；PSD 的
唯一 `ArtMesh` 图层名在导出 package 后被生成 ID 覆盖。公开 SDK 现支持参数
runtime ID，PSD 导入对唯一合法图层名保留 runtime ID；重建 wheel 后，真实
双眼工程的项目与搬迁 package 在组合姿态逐像素一致。

## S8：艺术资产改版后保留既有 rig

主持人从 PSD 生成一个可追溯的单图层美术修订版，并保留原交付模型作为待更新
工程。受试者需把修订应用到对应 ArtMesh，同时保留其他图层和 34 个参数的行为，
完成保存、导出与搬迁。它检验 PSD 图层到纹理 atlas / UV 的关联与增量更新能力。
目前预检发现 `ArtMesh15` 和 `ArtMesh14` 在交付模型的 2048×2048 atlas 中各有
独立 UV 包围框，均不与另外 23 个 mesh 的 UV 包围框相交；公开 SDK 已有
`replace_png_asset`。候选任务是从 PSD 对应眼部图层生成一份颜色修订，要求定位
atlas 中的目标区域并替换工程纹理，同时保留网格、变形器、绑定、参数和其他区域。
这只是可行性线索，尚须验证修订前后的多姿态画面、图集边缘采样以及工程/package
搬迁，不能据此声称 S8 已可发放。
只有在公开 SDK 的 oracle 路径、允许的第三方图像处理依赖和可接受的像素误差
都被预检固定后才发放；若缺少可行的增量更新接口，先把它作为系统能力缺口记录。

## 运行与归因

- 三位 Luna 各接收一个 S6 变体，在该关使用新会话；S7/S8 复用这三位的会话，
  `fresh` 与 `learning` 分开统计，不再每关重复开三次新对话。
- 任务包在仓库外，用 uv 创建并安装冻结 wheel。原始 clean 模型、oracle、其他
  trial 和判分器必须从受试包排除。同一系统用户的文件权限无法证明严格隔离；
  若仍使用桌面 subagent 手动实验，报告只给作品分，不填 `independent_success`。
- 每个失败先用冻结 oracle、正负控制和最小复现区分：SDK 无法完成、接口/文档
  难以发现、受试脚本问题、素材问题或判分器问题。修复后用原变体和未调优变体
  复验，不改写旧报告。
