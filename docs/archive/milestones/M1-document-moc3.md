# M1：Document 核心模型与 MOC3 导出

状态：已完成，2026-09-19 本机统一验收通过（macOS arm64 / Godot 4.7.2 / OpenGL）。依赖：现有 kasane-core、PurismCore 与 gd-cubism。返回 [总路线图](../ROADMAP.md)。

当前进度：已完成源数据/预览边界拆分，普通参数与完整 Keyform、正式嵌套 Rotation/Warp、Part/绘制属性/遮罩、编辑回归和通用运行包发布。2026-09-19 的历史验收通过全部必需门禁：7 项 CTest、59 项 Godot 集成检查、84 项 GPU 检查和 Purism C99 bundle；两个 Core 各 7712 项数值比较。后续回归分别运行 Core、Godot 和 GPU 检查。见 [验收与复现](../archive/M1-ACCEPTANCE.md)、[核心重构说明](../archive/M1-CORE-REFACTOR.md) 与 [写出映射](../archive/MOC3-WRITER.md)。已知 Godot 首次动态导入退出问题保留记录；M2–M6 不因此视为完成。

## 1. 交付结果

通过代码创建包含网格、嵌套变形、参数和 Keyform 的 Document；在内存中编辑、求值；导出新的 MOC3，由现有运行时加载并驱动。Document 不依赖 Godot 场景树，不通过写文件重载来更新预览。

本里程碑同时约束模型与写出能力。只有类型定义、只会保存 JSON、只会显示四边形，均不构成完成。

## 2. 输入与输出

- 输入：数据 API 创建的 Document、PNG 纹理槽和预览参数值。
- 数据输出：当前参数下的 drawable 几何、顺序、透明度、颜色、遮罩和纹理槽。
- 文件输出：`model.moc3`、`model.model3.json`、纹理文件、导出报告。PNG 作为包内独立文件。
- 文件版本：`csmMocVersion_50`，小端；支持集合见总路线图第 5 节。范围外的可选数据段按该版本格式规则写空，不伪造已支持特性。
- 验证入口：脱离编辑器 UI 的构造、导出和运行时对照程序。

## 3. Document 数据契约

| 数据 | 必需内容与规则 |
|---|---|
| Canvas | 原画尺寸、原点、pixels-per-unit；坐标与 UV 方向有单一书面定义 |
| ImageAsset | 稳定 ID、来源、尺寸；Mesh 引用 asset ID，导出时映射纹理槽 |
| Part | 稳定 ID、名称、组织父子关系；组织关系与变形关系分开 |
| ArtMesh | 稳定顶点 ID、基础位置、UV、三角形、纹理、Part / deformer 引用、绘制属性 |
| Rotation | 基础角度和 Keyform 的原点、角度、缩放、反射、透明度、颜色 |
| Warp | 网格行列、控制点、变换规则和 Keyform；局部坐标、边界、外推与运行语义对应 |
| Parameter | 稳定 ID、运行时 ID、名称、最小/最大/默认值；本轮普通非循环参数 |
| Binding | 目标、参数轴、各轴严格递增的关键值；轴顺序显式保存 |
| Keyform | 显式关键值组合下的对象属性；Mesh 位置、变形器属性、透明度、颜色、绘制顺序按对象类型定义 |

完整组合绑定按各轴关键值的笛卡尔积存放形态。缺组合、重复关键值、属性长度不一致时拒绝，不以最近形态补齐。同一目标属性不能有冲突的重复绑定。

内部对象 ID 与运行时 ID 分开管理；名称重命名不破坏引用。导出编码、长度、整数容量、索引限制必须定位到对象与字段，禁止截断。

## 4. 编辑与求值契约

1. 对象有遍历、创建、读取、修改、删除；几何和 Keyform 有实际批量写入。
2. 有引用的对象不能直接删除，返回引用者，显式解绑后删除。关系校验环和对象类型。
3. 已有 Keyform 的 Mesh 改拓扑时，一次提交全部受影响形态和顶点映射；缺数据拒绝。不能只替换基础几何。
4. 编辑基础数据、编辑指定 Keyform、设置临时预览值是三个显式操作；预览不修改持久化内容。
5. 修改产生对象级变化集合；派生结果可重建。源 API 不创建 Godot 节点、不加载图片、不写文件。
6. 复用 PurismCore 的绑定、插值、Rotation / Warp 算法，提取普通数据输入，保留原运行时适配与回归。不将完整 MOC3 内存结构当作可编辑模型。
7. 求值输出同时供 renderer 和数据检查读取，正常预览不调用文件导出器。

## 5. 实施顺序

1. **静态网格写出**：对照 `moc3.h`、`moc3.c`、`verify.c` 建立字段到 section/count/offset 的映射，写出带纹理槽的网格，由两个 Core 加载。映射记录默认值、容量、字节序、对齐和对应测试。
2. **参数与网格形态**：参数、绑定轴、关键值表、Mesh Keyform；验证端点、中点、多参数组合。
3. **变形器**：Rotation、Warp、两种嵌套顺序；内存求值与导出运行结果对照。现有简单 Warp 若不等价，替换实现并明确迁移或拒绝旧数据。
4. **绘制结构**：Part、顺序、透明度、颜色、三种混合、普通/反向遮罩；完成运行资源包。
5. **编辑回归**：删除、重绑定、拓扑替换后再次导出，不相关对象不变。

导出流程：校验 Document → 分配稠密索引 → 构建依赖与 Keyform 表 → 计算布局 → 写临时文件 → 校验 → 发布。结构与数值编辑都影响输出，不依赖输入 MOC3 字节补丁。

使用显式字段宽度和字节序，不 dump C/C++ 结构体或 revive 后的运行内存。多文件包在独立目录构建并验证后发布；失败保留原产物。

## 6. 模块与边界

- `kasane-core`：模型、校验、编辑 API、求值适配。
- `purism-core`：可复用算法/格式访问；保持已有 Core ABI 和回归。
- MOC3 编解码作为正式库代码，供 M1/M3 共用，不放在 demo。
- `kasane-godot` 提供 Rust GDExtension 适配；完整脚本接口在 M5 验收。
- 对照工具复用现有播放器；不等待独立 viewer。

## 7. 验收

遵守 [统一验收规则](../VALIDATION.md)。

| 用例 | 必须验证 |
|---|---|
| 静态网格与两张纹理 | 两个 Core 接受新文件；纹理槽、UV、拓扑、画布、资源描述正确 |
| 单参数三形态 | 关键值和中点正确；改中间形态后重新导出有对应变化 |
| 两参数 3×3、三参数 2×2×2 | 非对称形态验证轴顺序、组合插值 |
| 嵌套变形 | 两种顺序、非零原点、缩放/反射、Warp 边界外坐标 |
| 多层与遮罩 | 顺序、透明度、颜色、混合、普通/反向遮罩有数据与 GPU 证据 |
| 编辑后导出 | 新增/删除、重绑定、完整拓扑更新；旧缓存不决定输出 |
| 无效数据 | 缺形态、环、悬空引用、越界、非有限值、不可表示 ID 明确失败 |
| 实现复用 | 既有 Purism 回归通过，无未经对照的第二套近似算法 |

交付源码、字段映射、构造模型、运行包和对照报告。M1 通过前不能将“已定义 Document”标成“可导出 Live2D”。
