# SDK 渐进实验：2026-09-24 续轮记录

本轮按 [实验协议](../SDK-EXPERIMENTS.md) 使用仓库外任务包、uv 共享环境和安装后的
Python wheel。三位 `gpt-6-luna` subagent 各负责一份独立任务包，并顺序进入下一关。
S3-A 为 fresh；后续关卡保留前关经验，标记为 learning。它们不是一般用户成功率样本。

这些是桌面 subagent 手动会话，没有通过 `sdk_experiments.py run` 包裹模型 runner，
因此没有可靠的 agent 墙钟时间、完整工具轨迹或 token 费用；不声明协议中的
`independent_success` 或“预算内无提示成功”。作品、重放、搬迁、重复交付由独立判分器
验证，脚本和 notes 另由主持人阅读。以下的“通过”仅指作品层面的工程门槛。

## 问题与改进

### EXP-01：嵌套交付声明未被识别

A2 的原报告在 `original`、`replay` 和 `repeat` 都因找不到输出根下的
`result.json` 失败，尽管任务卡允许子目录布局。三份 A2 原作品均由冻结 worker
独立通过工程、包、搬迁和语义检查；旧验收重放留下的两份结果也通过。
[追认记录](/private/tmp/kasane-s3-round-20260924/host/trials/a2/adjudications/nested-result-20260924/report.json)
保留原失败报告。CLI 现接受输出根或交付子目录中的声明，多份时选最新写入的一份；
任务卡明确此协议，新增嵌套声明集成测试。该问题归因于任务/判分协议，不能记作 SDK
运行失败。追认不是原冻结 CLI 的正式通过，也不填成有完整轨迹的无提示成功。

### EXP-02：评估记录字段和坐标空间易被猜错

A1 和 A3 曾把 `DrawableSample` 猜成有 `mesh_id` 或 `name` 字段；V1 曾猜测
`ObservedFrame.size`，V2 在自检中混用源画布像素与运行时坐标。受试者均自行纠正，
最终作品通过。这些是公开文档可发现性问题：API 参考现明确 `DrawableSample.id`、
`ObservedFrame.width/height`，并指出观察像素、runtime 与父级局部几何的区别。
S4-B 确认轮用于检验更复杂的坐标使用，三份均成功。

### EXP-03：S4-B 首版可绕开父级坐标推导

P2 发现目标终点真值恰等于起点，直接复制起点关键形态即可得到正确图像。
这是夹具设计问题。v2 把真值终点设为不同于起点的位置，保留相同的任务说明和
固定旋转父级，重新跑正负控制与三份学习会话。C1–C3 的原作品、重放、几何、
固定观察像素和报告均通过；脚本与 notes 显示它们依据新图像重新推导局部修正。

### EXP-04：接手工程须在控制检查前冻结

首个 S5-B 实验目录在 `init` 预检时失败，原因是底座在运行正负控制后才复制
`--handoff-project`，控制脚本无法读取接手输入。此时没有发放任何 trial，也没有
受试结果。CLI 已改为先冻结输入工程，再运行控制；新增集成测试验证复制顺序。
重新初始化 `/tmp/kasane-s5b-round2-20260924` 后，正负控制及 H1–H3 正式验收通过。

### S5 的接手证据

E2 通过的真实工程作为三份 H 任务包的共同输入；不是由控制脚本直接生成的标准答案。
E1–E3 的 `Expression` 各驱动嘴部和左右标记，五档几何与端点像素通过。
H1–H3 仅改两个标记原有绑定的终点，使其相对各自起点上移 3 个源画布像素；
嘴部行为、绑定 ID 与标记起点保持。判分器对原作品和新目录重放均重新打开工程，
核对公开状态、五档采样及端点渲染。H1、H2 的 notes 记录了自检或环境路径错误并
自行修正；H3 未记录障碍。这些自述不能替代完整工具轨迹。

## 当前结论与限制

S3-A/B、S4-A/B、S5-A/B 的已运行工程任务均有正确交付证据；S4-B 的 v2 确认轮
和 S5-A/B 各满足三份同版本作品与重放通过的工程门槛。依赖环境由同一轮受试者共享：
例如 Pillow 安装会影响后续受试者，不能把后续查图成本当作 SDK 自身效率提升。
本轮没有完整 runner 轨迹，故不能量化首次有效产出时间或断言严格隔离下的独立成功。
下一轮应增加新的保留变体与独立 runner 记录，再评估更广泛的可迁移性；不把本轮
小样本作品通过率当作总体成功率。
