## 递进路线

每次只增加一个主要困难。先把下面两项 S3 增量任务做实，再开放 S4，最后进入 S5。

| 顺序 / ID | 任务 | 相比历史新增的困难 | 条件 / 时间预算 |
| --- | --- | --- | --- |
| 1 / `delivery-transfer`（S3-A） | 导入、指定局部修改、保存、导出、搬到新目录后重开 | 交付物能离开原输入目录使用；编辑结果跨导出保持 | CPU，20 分钟 |
| 2 / `resource-recovery`（S3-B） | 工程纹理失联，利用提供的素材库恢复并交付 | 从结构化错误与资源属性定位匹配文件 | CPU，20 分钟 |
| 3 / `visual-locate`（S4-A） | 从参考图找出偏移部件，修正指定参数的终点 | 不告诉 agent 具体对象名称或修正量 | GPU + 图像查看工具，25 分钟 |
| 4 / `visual-parent`（S4-B） | 同样的视觉修正，但目标位于带旋转的父级下 | 屏幕/画布/父级局部坐标的转换 | 与 S4-A 相同，25 分钟 |
| 5 / `compose-expression`（S5-A） | 让两个部件共同响应一个表情参数 | 组合行为、中间状态与可继续编辑性 | GPU，30 分钟 |
| 6 / `handoff-revision`（S5-B） | 新会话接收作品，按追加需求修改并交付 | 接手他人的工程及说明，不依赖作者会话 | GPU，20 分钟 |

时间是本轮预设上限，不是已有完成耗时的统计估计。夹具正控制跑通后，正式发放前
可以统一调整；正式批次中不按受试表现临时延长。

## 本轮受试安排

按用户修订后的安排，使用 **3 位 `gpt-6-luna` subagent**，每位从 S3-A 开始，
通过验收后保留上下文进入下一关。只有 S3-A 标为 fresh；S3-B 至 S5-B 标为 learning。
每关固定任务版本，三份作品与重放均通过才进入下一关。S4-B 首版夹具存在可复制
起点的捷径，另起 v2 确认轮；同三位受试者继续参与，不合并两个版本的结果。

每轮共享 uv 环境。首次安装依赖与后续继承的依赖分别记在受试 notes 中；由于未用
`run` 包住模型 runner，本轮不提供耗时、token 或预算内无提示完成结论。

第一批发现问题后，优先修复出现至少两次、或单次造成错误交付/破坏输入的问题。
一个批次内不修改 SDK、公开材料或判分规则；确有判分器错误时暂停该任务，保留原报告，
修复后重判原作品并复验控制。任务语义或 SDK 改变，则以新版本、新会话重新运行。

## S3-A：交付迁移

受试文字：[任务卡](tasks/delivery-transfer.md)。

**输入准备**：提供完整 model3/MOC3/纹理包、`request.json` 和公开文档。
夹具至少有两个可区分的 mesh、一个普通参数、一个完整两端绑定；请求只修改其中
一个终点。目标 mesh 和参数的稳定标识、坐标空间、修改量在 request 中明确列出。
这一关不同时测试对象猜测、视觉理解或复杂父级变换。

优先生成项目自有的两部件夹具，或将现有 `tests/fixtures/external_v50` 作为导入候选。
后者的 model3 引用了物理和动作文件，不能默认把它当成所有引用均齐全的交付包。
主持人须在预检中明确任务只覆盖模型几何/参数/纹理，清理自有夹具中不属于任务的
辅助引用，或公开说明这些不支持内容及可接受 warning，不能隐藏扣分。

**独立验收**：

1. 与导入后的基线相比，目标终点修改正确；0/0.5/1 的几何与预期一致，绝对容差 `1e-6`。
2. 保存工程的其他对象、关键形态、参数、资源内容和身份保持不变。资源 `source` 与
   会话 `version` 的合法变化不作为失败。
3. 导出结果含 model3、MOC3 与引用的纹理，能在一个新的 Session 中导入，诊断通过。
4. 复制 project 和 package 到主持人的新接收目录；在仅可见接收目录的子进程中重开/
   导入并采样，或逐项确认解析后的所有必需引用位于接收目录，再执行重开与采样。
   仅在原目录中打开成功不算通过。不要删除或临时重命名受试者输入来模拟搬迁。
5. 对导出再导入的结果，按公开 runtime 标识/映射、参数定义和求值检查语义等价，
   不强制要求重新导入时生成的 authoring UUID 与原工程一致。
6. 在新输出目录重放；再在同一输出根运行一次，验证重复交付不会破坏前一次作品。
   允许返回旧的正确产物或产生编号新目录，不限定调用顺序；必须返回实际路径。

**控制**：正确交付通过；合法不同文件布局通过；未应用修改、缺纹理、遗留指向
原目录的资源引用、非目标改变分别失败。另用等价但 authoring UUID 不同的导入结果，
确认判分器不会把纯身份重建误判成内容丢失。

## S3-B：资源恢复

受试文字：[任务卡](tasks/resource-recovery.md)。

**输入准备**：提供一个可打开、但恰有一项纹理引用失联的 Kasane 工程，以及三个
候选 PNG。正确候选与记录的尺寸/SHA-256 相符；两个干扰项中，一个尺寸相同但
内容不同，另一个尺寸不同。文件名不能直接透露答案。几何和工程结构没有其他故障。

主持人先确认 SDK 能打开此状态并查询资源记录与诊断。若加载入口直接阻断查询，
这是夹具/能力前提未满足，应先调整任务到受支持的恢复路径，不能把无解题交给受试者。

**独立验收**：失联资源恢复到同一内容；所有非资源内容及 ID 保持；诊断无错误；
保存和导出自包含，搬迁验证与 S3-A 一致。目标资源允许路径变更，名称/身份/内容
必须保持。notes 中能指出失败资源及选择候选的证据，不强制匹配特定错误消息文本。

**控制**：正确候选通过；同尺寸错误内容、空白替代纹理、仅把诊断写成成功、
直接修改输入工程的方案分别失败。没有恢复就抛异常属于任务失败；若日志证实
依赖下载/运行设施故障，单独记录，不借机修改资源验收标准。

这一轮不同时加入保存冲突、损坏 MOC3 和 GPU 不可用。保存到已有目标已在 A 中
通过重复交付覆盖；其他异常以后作为独立变体，避免一次失败对应多个原因。

## 后续 S4：视觉定位与坐标迁移

S4-A 使用至少三个互不遮挡、纹理不同的部件与不指示角色的名称。向受试者提供
当前工程、同一观察设置下的目标图和参数采样值，只告知“一个部件的终点位置偏移，
其他内容应保持”。禁止直接修改参考 PNG/纹理，允许安装图像分析依赖。
交付修改后的工程、0/0.5/1 帧、contact sheet、可定位到原始图像的观察报告与 notes。

S4-B 保持同样的任务说明、部件数量与偏移规模，仅改变目标的父级：加入固定的
非零旋转。仍只允许修改目标 mesh 的终点几何，不允许通过修改父级或相机拟合图片。
任务明确要求其他关键形态与场景保持，具体修正量由图像和公开工程信息推导。

主持人从真值工程生成参考图，然后仅扰动目标终点生成输入；不把真值工程或
顶点差分发给受试者。通过独立几何检查、非目标保持和像素检查共同判分，不能
只看受试者复制出来的参考图或自报 `changed_pixels=0`。

首版固定 Observer 尺寸/视图/后端。pilot 先确认同一真值重渲染能逐像素一致，
才将零像素差作为公开标准；否则在发放前用重复渲染与故意错误的图校准并公布容差，
不得看到受试结果后放宽。始终额外检查目标局部区域，避免整图平均掩盖小部件错误。

GPU/图像工具的正控制失败时，记为环境未就绪，不消耗受试名额。实际执行中，
三位既有受试者顺序完成 S4-A、S4-B；S4-B 首版夹具存在捷径，又用同三位受试者
做 v2 确认。两个版本的结果分别记录。

## 后续 S5：多部件与接手修改

S5-A 从既有可编辑工程出发，要求一个表情参数同时驱动两处独立变化，例如嘴部
纵向张开与两侧标记上移。提供端点参考图，要求 0、0.25、0.5、0.75、1 的状态
连续、没有意外消失或非目标漂移。定量目标写进任务，主观“自然”另作人工评价，
不把未公开审美偏好作为硬性失败条件。先不同时要求新绘画、全新拓扑和时间轴动画。

S5-B 将一份通过验收的 S5-A 作品固定为输入，所有接手者收到相同工程和简短说明，
在保留前关经验的会话中追加“减小两侧标记的位移幅度，保留嘴部行为”的需求。要求重开、局部
修改、重新交付。只给交付资料，不给作者完整轨迹。用这一步检验作品是否可接手，
而非原作者能否再次运行自己的脚本。不同输入作品须分别记录，不混成单一成功率。

## 记录和决策口径

不用综合百分制掩盖使用障碍。每次报告保留：

| 字段 | 含义 |
| --- | --- |
| 作品 / 重放 / 搬迁 / 重复交付 | 分别通过、失败、未运行；不把未运行算通过 |
| 无提示预算内完成 | 有真实运行计时、轨迹和主持人审阅才判定 |
| 首次有效产物 / 总耗时 | 从自动时间戳获取；无时间戳留空，不用自报补齐 |
| 阻碍与恢复 | 错误发生位置、重复次数、实际恢复行动和额外代码 |
| 依赖 | 开始/结束清单、安装耗时（可获得时）、是否继承前人依赖 |
| 归因 | SDK 实现、API、文档、运行环境、任务/判分器，附轨迹位置 |

升级到下一关的工程门槛：正负控制有效；同版本确认批次的 3 次均交付正确、重放
通过、没有已知人工提示或输入破坏。若 2/3 成功，先解释失败并针对性复测，不直接称为
“稳定”。这只是小样本工程门槛，不是对成功率置信水平的声明。

每次改进至少关联一条使用证据、一个可检验的假设、原任务复测和一项新变体。
新变体改变素材组合或层级，而不只是随机 UUID。变体被用于调优后转入回归，
下一次再补充新的保留变体；不要提前把保留任务答案放入受试可读材料。

## 原设计的底座接入清单（历史记录）
