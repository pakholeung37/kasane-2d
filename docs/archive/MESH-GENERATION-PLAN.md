# 自动 Mesh 生成：集成方案与实验方向

日期：2026-09-25。本文结合当前 Kasane 2D 源码与指定的 mesh 调研，给出实施方案。已执行现有 SDK 测试和一个独立 Spade 语义实验；完整图层自动建网及质量排名尚未验证。

建议主线：**原始图层 alpha → 安全轮廓 → 边界约束与内部布点 → 约束 Delaunay → 几何质量检查 → SDK 原子提交 → Observer 动态验收**。先解决未绑定 PSD/PNG 图层的初次建网，再处理已有动画的重建网格。

## 1. 调研依据与现状

本次读取的正确来源是 ChatGPT 对话“编译并启动项目”（`6ab5d29d-94dc-83ec-a720-1775ca041a27`），内容确实是 Live2D 式 mesh 生成调研。此前本文引用了另一个编译任务并转向 Umamo，现已纠正；这里的算法方向以本次指定调研和当前 Kasane 源码为依据。

调研的关键结论是：**轮廓决定生成域，支持线和尺寸场决定布点，CDT 决定连接，实际动作决定质量。**内外圈并不自动限制形变传播；Cubism 文档的内外边距、点间距参数也不能证明其内部使用某一特定算法。[官方参数说明](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit/)

检查时 Kasane HEAD 为 `cea3d742e8b3029155cd6076fc4cc5f267194622`。工作区存在进行中的未提交改动，以下依据包括实际工作区源码，不能仅用 HEAD 复现。

| 现有能力 | 证据位置 | 对集成的含义 |
| --- | --- | --- |
| PSD 图层生成四顶点、两三角形矩形；UV 为 0..1 | `modules/kasane-psd/src/lib.rs` 的 Mesh 构造 | 能作为新算法输入和中立渲染对照 |
| 矩形规则细分，保留角点 ID | `modules/kasane-sdk/src/geometry.rs::rectangle_grid_geometry` | 已有确定性基线；不支持任意轮廓 |
| 矩形细分时迁移普通关键形态、BlendShape、glue | 同文件 `remesh_rectangle_grid` | 可复用事务组织方式；其插值算法只适用于标准矩形 |
| 带版本检查的原子拓扑替换 | `modules/kasane-sdk/src/edit.rs::replace_topology`、`types.rs::TopologyReplacement` | 正式生成操作应走此提交入口 |
| 核心验证完整旧顶点映射、全部相关绑定与 glue | `modules/kasane-core/src/document/meshes.rs::replace_mesh_topology` | 删除顶点必须显式映射为 None，不能漏报依赖 |
| 几何诊断含小三角形、绕序不一致、画布越界 | `modules/kasane-sdk/src/diagnostics.rs` | 尚不足以验收轮廓覆盖、交叉边、孔洞和动态翻折 |
| Python 包装 Rust；Observer 输出渲染图 | `docs/ARCHITECTURE.md` | Rust 拥有正式建模规则；Python 批量跑实验、整理报告 |

当前没有 alpha 轮廓、偏移、CDT 自动建网模块。已有 Shirousagi X 轴实验记录了 1,408 个头部网格顶点，其中 707 个不在参考网格的三角形域内，采用最近顶点位移回退。这说明规则矩形网格值得作为改进对象，但**不表示这 707 个点全部无用，也不证明换成 CDT 就能消除迁移误差**。该数字来自已有实验记录，不是本次重跑：[头部 X 实验](experiments/SHIROUSAGI-HEAD-X.md)。

## 2. 首轮比较哪些算法

| 候选 | 实验作用 | 预期取舍，尚待实测 |
| --- | --- | --- |
| A：现有矩形规则网格 | 必保留的基线 | 简单稳定，但透明区域也耗费顶点，形状边缘不能主动加密 |
| B：安全轮廓 + Earcut | 验证轮廓、孔洞和 UV 链路 | 能做多边形三角化，但不能代替内部密度设计；直接结果可能不适合形变 |
| C：安全轮廓 + 均匀内部点 + CDT | 第一阶段主候选 | 约束边界、孔洞，同时控制内部采样密度 |
| D：C + 内侧支持线 + 边界密、内部疏的尺寸场 | 边缘带主候选 | 单独验证外扩/内缩与边缘带的价值；窄部位允许无内圈 |
| E：D + 人工特征线 / 动作误差驱动加点 | 后续候选 | 把预算分配给眼睑、嘴角、耳根等局部形变；依赖额外动作或语义输入 |

Rust 首选试验库为 [Spade](https://github.com/Stoeoef/spade)：提供约束 Delaunay、细化及稳健几何谓词。其[细化接口](https://docs.rs/spade/2.15.1/spade/struct.RefinementParameters.html)支持面积、角度和新增顶点预算。文档中的 `exclude_outer_faces` 是从细化中排除外部区域，输出时仍需过滤对应面；必须检查 `refinement_complete`，不能将耗尽预算当成成功达到质量指标。

**D 组不能直接沿用 C 组的自动内外排除。**新增闭合支持圈后，Spade 的约束边奇偶分类可能将支持圈内部判为孔洞。本次最小实验已复现，详见第 8 节。应始终在自身数据里区分 `OuterBoundary / HoleBoundary / SupportCurve / FeatureCurve`；只有前两者改变生成域。

前处理的首轮候选：

| 环节 | 建议试验 | 要验证什么 |
| --- | --- | --- |
| 轮廓 | 像素格边界作覆盖基准；[`contour`](https://docs.rs/contour/latest/contour/) 的 Marching Squares 作平滑候选 | 前景 4/8 连通策略、对角歧义、半透明细线、采样坐标偏移；先补透明框并换回原图坐标 |
| 外扩/内缩 | Clipper2 路线先行 | [`clipper2`](https://docs.rs/clipper2/latest/clipper2/) 是 C++ 封装；[`clipper2-rust`](https://docs.rs/clipper2-rust/latest/clipper2_rust/) 是纯 Rust 移植。对相同凹角/细缝/内圈消失夹具比较，再选正式依赖 |
| 内部布点 | 确定性错列格点先行，固定半径 Poisson-disk 作对照 | 点与约束边的距离、方向偏差、预算和重复性；可变半径采样另行实现，不直接替换固定半径参数 |
| 质量细化 | 先比较关闭/开启有限 Spade refinement | 记录输入/新增顶点和未达标原因；空间变化的 `h(x)` 由采样器或自有细化调度实现，不等同于全局最大面积参数 |

SDF、DistMesh、Advancing Front 留作后续替代实验。第一轮先打通一种轮廓和偏移组合，避免同时更换所有模块。

对照可用 [earcutr](https://github.com/frewsxcv/earcutr)。[上游 Earcut](https://github.com/mapbox/earcut)明确不保证复杂退化或自交输入的正确性，因此它不能替代输入轮廓验证。依赖版本在实施时锁定并写入实验报告。

不建议首轮引入 GPU 建网或多个语言运行时。此任务首先要回答“同样的顶点预算下，哪种拓扑更适合本项目形变”，再测速度。

## 3. 建议的集成边界

```text
PNG / PSD 图层 RGBA + 图层原点
            ↓
Rust 纯算法：mask / contours / sampling / triangulation / quality
            ↓
候选 geometry + 来源映射 + 指标 + 警告
            ↓
kasane-sdk：检查版本、构造 TopologyReplacement、一次提交
            ↓
kasane-python：调用与批量报告
            ↓
Observer：中立姿态、变形姿态、保存重开、导出后检查
```

实验期在 `kasane-sdk` 下组织独立纯算法模块即可；若 PSD 导入器之后要直接调用，再提取不依赖 SDK 的 `kasane-mesh` crate，避免 PSD → SDK 的反向依赖。首版从导入后的 SDK 操作接入，暂不改变 PSD 默认导入行为。

建议的新增 API 形状（尚未实现）：

```rust
generate_alpha_mesh(raster, options) -> Result<GeneratedMesh, MeshGenerationError>
plan_alpha_remesh(session_snapshot, mesh_id, options) -> Result<RemeshPlan, SdkError>
apply_remesh_plan(session, plan, expected_version) -> Result<EditReceipt, SdkError>
```

`GeneratedMesh` 使用算法局部顶点下标；SDK 负责分配持久 VertexId，并将三角形下标转换为 VertexId。`RemeshPlan` 固定来源版本、输入资产哈希、算法版本、参数、候选几何、依赖迁移结果和质量报告，供预览和原子提交使用。正式 API 命名可以在实验稳定后确定。

建议代码落点（除列出的现有入口外，以下模块尚未实现）：

- `kasane-sdk/src/mesh_generation/`：`contours / offset / sampling / triangulation / quality`；输入解码像素和明确的坐标映射，返回候选，不修改 Document。
- SDK session 操作：复用 `kasane-project::decode_png` 及资产校验；生成在编辑事务外完成，提交时再次验证来源版本与资产哈希，通过 `EditSession::replace_topology` 一次提交。若新增 padding 资产，资产描述与 mesh 更新纳入同一编辑，资源文件先准备、失败时不发布工程。
- `kasane-python/src/geometry.rs` 与 Python `geometry.py`：类型和错误适配；正式几何规则保持在 Rust。实验脚本负责扫参数、调用 `Observer.observe_run`、汇总图片与指标。
- 线框、轮廓和密度叠图先由实验报告生成；当前 Observer 提供渲染、裁剪和接触表，不能当成已经存在的线框查看器。基础运行时继续消费现有 Mesh 数据。

首版参数建议覆盖：`alpha_min`、轮廓容差、`outside_margin`、`inside_margin`、`boundary_spacing`、`interior_spacing`、顶点上限、孔洞策略、随机种子。**距离统一为源图层像素，alpha 使用 `alpha >= alpha_min`，保真基线取 1。**Cubism 的透明阈值及基于 1024 纹理尺寸的边距定义与此不同，不直接照搬数值。先支持 root-space、标准 UV、无普通 binding/BlendShape/glue 的 PSD/PNG 初始矩形；不满足前提时返回明确错误。

## 4. 流水线中必须处理的细节

1. **用素材 alpha，而非最终合成画面提轮廓。** opacity、可见性、mask、混合模式和遮挡保留为模型属性；不能把当前被遮住的像素永久裁掉。全透明层返回明确的空结果/跳过报告。
2. **区分连通岛与孔洞。** 建立轮廓包含关系；对重复角点、接触环、交叉边先修复或明确拒绝。一个 mesh 可以含多个互不相连的三角形组件，无需自动改成多个模型对象。
3. **简化后重新验证。** 检查自交、环间交叉、孔洞归属和覆盖误差；失败时降低容差，必要时回到精确轮廓。精确轮廓仍可能有弱简单接触点，不能仅设置 epsilon=0 就跳过规范化。
4. **保留抗锯齿边缘与可控余量。** 阈值偏高会丢失低 alpha 像素；简化弦也可能向内切。阈值 1 作保真基线，其他阈值必须用 alpha 加权漏盖面积和实际渲染验证。膨胀可能合并岛、填平细孔，需记录拓扑变化。
5. **边界重采样后再布内部点。** 先测确定性三角格点，再测固定种子的 Poisson-disk。轮廓拐角和人工特征点保留；避免内部点紧贴约束边产生狭长三角形。
6. **CDT 需要完整区域分类。** 外环、孔洞边成为约束，输出只取有效域中的面。只按三角形重心是否落在 alpha 中筛选，不能可靠阻止跨孔洞、凹口或窄缝的三角形。后续加入内部特征线时，应单独标记边界边，避免把任意约束都当作区域边界。
7. **统一坐标与 UV。** 首版图层局部点 `(x,y)` 映射为 `position=(left+x,top+y)`、`uv=(x/W,y/H)`；使用像素角点坐标，不混入半像素偏移。挂父变形器、atlas UV、旋转 UV 等场景另行实现映射，不能套用该公式。
8. **外扩与纹理边缘一起验证。** 当前 `modules/kasane-render-wgpu/src/pipeline.rs` 使用 ClampToEdge。几何扩到原图之外可能重复最外行像素；首版余量限制在现有纹理域内，若需越界则同时生成透明 padding 资产、重算 UV、更新资产哈希。不要仅把 UV 钳到 0..1。
9. **确定性与资源预算。** 固定种子、轮廓顺序、点插入顺序、共圆 tie-break 策略与输出编号；内部 f64，转换为项目 f32 后复查重合点和零面积。设置像素、轮廓点、顶点、细化次数预算；初期顶点上限不高于现有网格工具的 65,536，并验证导出约束。

### 边缘带的具体构造

从规范化的有效域 Ω 计算外扩域 Ωout 与内缩域 Ωin。外扩域边界是生成域约束；内缩域边界只是支持线，**其内部仍应填三角形**。支持线和外边界一起进入同一 CDT，不假设点数一致，不单独三角化后强行缝合。外扩后的岛合并、洞收缩以及内缩后的分裂/消失必须写入报告；需要保持岛独立时逐岛处理并限制余量，不能默默合并。

内圈消失时首版直接省略该段支持线，保留窄区覆盖与受控布点；中心线属于后续发束模板。尺寸场可先取 `h(p) = min(h_interior, h_boundary + growth × distance_to_boundary(p))`，再叠加特征/动作要求。将距离定义为到可见轮廓的距离，设置最小间距和变化速率，避免支持线两侧密度突变；该公式是待测设计，不是 Cubism 的公开算法。

区域分类应只依据 Ωout 的真实外环/孔洞：约束交点预先切分，细化拆边后仍保留边的类型与来源。C 组没有支持圈时可以评估 Spade 内建排除；D 组最小对照可关闭自动排除、细化整个凸包后按真实域选面，但凹形/多岛会浪费预算，**这只是诊断基线**。正式 D 组需要按真实域挑选待细化面、执行受预算限制的插点及约束边拆分，或评估支持显式域标记的后端。仅在末尾改一次面筛选无法补回被跳过的支持圈内细化。

若图层四周新增 p 像素透明 padding，在原图局部坐标中仍使用 `position=(left+x,top+y)`，UV 改为 `((x+p)/(W+2p),(y+p)/(H+2p))`。可见内容位置不变；用贴边不透明像素与半透明颜色边缘检查采样接缝。padding、亚像素采样约定及过滤足迹都必须进入中立渲染对照。

## 5. 已有动画的 remesh 单独推进

`TopologyReplacement.vertex_mapping` 表达旧顶点身份去向，不是插值权重。需要另建每个新点的来源：`old_triangle + barycentric_weights`，用同一权重迁移 base position、UV、普通关键形态位置和 BlendShape 位移；glue 锚点优先作为固定点保留原 ID。UV 有重叠时查找可能不唯一，应带 chart/旧三角形归属，不能全图按 UV 猜测。

**关键限制：在新顶点处重采样正确，不代表新三角形内部处处正确。** 新边跨越旧三角形边界后，会把两段不同的仿射变形重新插值成一段。现有矩形 remesh 要求带绑定时 rows=columns，正是为了保留旧对角线。

分成两个明确模式：

- 保持模式：新网格在旧三角形内做细分，旧边作为约束；优先保持旧分片仿射场。对非线性父 warp、glue 求值等仍需做实际姿态检查，不能据此承诺最终渲染严格不变。
- 优化模式：允许新连边，报告关键姿态和中间姿态误差；仅作为可预览、可撤销操作。新增点超出旧网格域、缺少映射或依赖不完整时显式失败，不静默采用最近点投影。

先做无绑定初次建网，再做保持模式，最后考虑带误差预算的优化模式。这也避免把网格生成质量和动画迁移误差混在同一实验里。

## 6. 实测设计

### 输入集

- 合成夹具：空图、全不透明矩形、圆、凹 U 形、环形孔洞、多个岛、孔中岛、1 px 细线、尖角、斜向接触、相邻窄缝、低 alpha 渐变边、贴图边缘非透明。自生成素材可以进入回归测试。
- 真实素材：从 `models/local/Shirousagi/Shirousagi.psd` 重新导入无绑定工程，先选脸 `ArtMesh24`、耳 `ArtMesh27/26`、嘴缘 `ArtMesh17`、瞳孔 `ArtMesh15`、腮红 `ArtMesh23`；再扩展全部 24 层，包含隐藏替换层。对应关系见现有 `shirousagi_head_xy.py::LAYERS`，运行时仍要检查 ID 与资产哈希。
- 动态输入：P0 用新导入无绑定图层；P1 使用自造且连续可求值的弯曲/压缩/局部位移场；P2 再使用现有 `output/head-xy-experiment/result/project` 的副本验证已有绑定迁移。

### 公平比较

先固定相同的 mask、轮廓容差和余量，只比较三角化与内部布点；再固定胜出候选研究前处理参数。避免不同算法使用不同轮廓后，把漏边问题误判为三角化质量。

分两层比较：C 与 D 的消融试验共享轮廓、预算和变形场，只改变支持线/密度分配；A 与 C/D 的端到端对比则允许生成域不同，但以同一原始 RGBA 内容和可见采样点评分，额外透明覆盖单独记录。Earcut 只作为轮廓填充基线。

首批实验参数可从以下范围开始，均为待验证范围而非已确定产品默认值：alpha 阈值 `1/8/32`，简化容差 `0/0.5/1 px`，余量 `0/2/4 px`，目标点间距按图层尺寸分成疏/中/密三档。先逐项扫描，不做所有参数的笛卡尔积。

同时给出“相同顶点预算”和“达到相同覆盖/变形误差”两种曲线；记录实际 V/T 数，Earcut 边界基线无法消耗相同内部点预算时明确标注，不强行宣称等预算比较。

可先使用每层 `64/128/256/512` 顶点的试验预算，轮廓本身超过预算时标记不可行，不为凑点数删除发梢；规则矩形网格记录实际点数并在误差—顶点数曲线上比较。

### 动态测试必须有独立参考

在统一的源图层采样点 x 上，给定连续参考变形 F；若 x 在候选三角形内，用重心权重计算 `F_mesh(x)=Σ λᵢ F(vᵢ)`。比较 `||F(x)-F_mesh(x)||` 的 alpha 加权 RMS、P95、最大值，分别报告轮廓带和内部；漏盖的 x 单独计为覆盖失败，不能从统计中丢掉。

- 仿射平移/旋转/缩放：作为零误差控制组，误差只应来自数值精度；此组不用于评判密网格优势。
- 弯曲：在归一化坐标中试 `F(x,y)=(x+a y²,y)`，使发根与发梢的位移梯度不同。
- 局部变形：例如 `F(x,y)=(x,y+a exp(-((x-cx)²+(y-cy)²)/σ²))`，在嘴角/眼睑附近扫描中心和幅度，避免只挑有利于某种网格的位置。
- 项目 warp：在参考采样点上独立求值父 warp，并对候选 mesh 走正常求值链；所有候选使用相同变形器参数、画布及 Observer 视角。

前两种非线性示例并非完整的耳朵/闭眼动画，而是可控插值误差探针。参考场的幅度/频率留出一组不参与调参，防止 E 组仅拟合训练姿态。三角形面积符号与中立姿态比较，并和参考变形的局部方向比较；实际闭眼允许接近退化，不能一概要求所有真实姿态面积远离零。

### 指标与初始验收线

| 维度 | 记录内容 | 首轮判断方式 |
| --- | --- | --- |
| 拓扑 | 交叉边、零面积、重复面、非法索引、缺失约束、组件/孔洞变化 | 有效输入的错误为 0；无法处理应明确失败 |
| 覆盖 | alpha 加权漏盖面积、额外覆盖面积、边缘最大偏差 | 几何域覆盖和渲染差分同时看，防止透明区掩盖错误 |
| 形状 | 最小角、角度分位数、长宽比、三角形面积分布 | 看分布；原图尖角与细线不强制套用统一最小角 |
| 中立画面 | 与原矩形贴图的 premultiplied RGBA 差分、局部边缘放大 | 先争取无可见漏边；容差按渲染器数值基线校准 |
| 动态画面 | 位移场采样误差、面积比、相对中立姿态的符号翻转、接缝 | 用同一连续变形场和稠密参考采样比较，不能只比不同拓扑的顶点 |
| 成本 | 分阶段耗时、总耗时、峰值内存、V/T、失败率 | release 构建，多次运行报告中位数和 P95，分开记录图像 IO |
| 工程集成 | 失败回滚、版本冲突、undo/redo、保存重开、导出重导入 | 对象身份/依赖一致；重开前后几何一致，渲染按约定容差检查 |

Shirousagi 动态迁移验收可扫 `X,Y∈{-30,-15,0,15,30}` 的 25 个组合。比较 remesh 前后的同一工程，交付模型渲染只作为额外美术参考；不能把现有 rig 与交付模型的差异归因于新网格。

建议每次实验输出到新的 `output/mesh-generation/<run-id>/`：`manifest.json`（输入哈希/版本/参数）、`metrics.json/csv`、候选网格 JSON、轮廓/线框叠图、中立与动态差分图、失败样本、工程副本。报告明确哪些环节执行成功、失败或跳过。

## 7. 推荐实施顺序

1. **P0：首个端到端对比。** 自生成夹具 + 首批 6 个真实图层；A/B/C 三组；只做无绑定初始建网。交付可重复运行的 Rust 实验入口、Python 报告脚本、网格叠图和覆盖指标。先验收不漏、不穿、不误填洞。
2. **P0.2：边缘带验证。** C/D 同预算对比，测试窄处内圈消失、闭合支持圈不成洞、透明 padding，以及动态误差收益；几何质量细化做开/关消融。此阶段回答调研中最关心的“加粗 mesh 带有没有实际价值”。
3. **P1：正式 SDK 接入。** 形成 `plan/apply` 操作，补版本、历史、保存/导出验收；再试 E 组特征约束和动作误差加密。通过后才考虑 PSD 导入可选参数。
4. **P2：已有 rig 重建。** 映射普通关键形态、BlendShape、glue 和父空间；先保持旧边，再评估优化模式的误差预算。对 atlas/重叠 UV 单独立项测试。

当前最值得先实现的单项是：**安全 alpha 轮廓 + 均匀内部布点 + Spade CDT，接入 Shirousagi 原始 PSD 的无绑定图层，和现有规则网格做覆盖及受控形变对比。**

| 情况 | 顶点 / 三角形 | 按自动排除结果保留的面积 | 所有有限面的最大面积 | refinement_complete |
| --- | ---: | ---: | ---: | --- |
| 只有外框 | 56 / 86 | 100 | 1.892090 | true |
| 加支持圈，开启自动外部排除 | 51 / 76 | **84** | **4** | true |
| 加支持圈，关闭自动外部排除 | 52 / 78 | **100** | 2 | true |
| 只有外框，新增顶点预算为 0 | 4 / 2 | 100 | 50 | **false** |

解释：同一 4×4 内圈若表示真实孔洞，面积 84 正确；若表示支持线，应该仍覆盖 100。自动排除把圈内跳过；即使把这些面重新加入输出，其最大面积仍为 4，超过目标 2。`refinement_complete=true` 只针对本次纳入细化的域，不代表作者想要的整个 mesh 都合格。这是集成语义问题，不是 Spade 的错误。

```sh
cargo run --release --locked --manifest-path docs/experiments/mesh-cdt-probe/Cargo.toml
```
